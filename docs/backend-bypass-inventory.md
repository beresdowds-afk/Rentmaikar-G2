# Backend Bypass Inventory

**Scope:** Static repository review of the `Supabase-direct-call-refactoring` target intent. The checked-out branch is `copilot/supabase-direct-call-refactoring`. This inventory records code-defined paths only; it does not establish which Edge Functions, webhooks, cron jobs, secrets, or Cloud Run revisions are active in a live project.

The frontend adapter in `src/integrations/supabase/client.ts` intercepts only `supabase.functions.invoke()` calls. `LOCAL_GATEWAY_FUNCTIONS` selects `/api/functions/:name`; `PAYMENT_AUTHORITY_FUNCTIONS` selects BackendBridge; neither set proves that the backend executes the operation locally. `backend/src/routes/functions.ts` first proxies names outside `AUTHORITATIVE_BACKEND_FUNCTIONS` to Supabase and then runs local switch handlers only after a failed/missing upstream response. Direct `fetch()` and dynamically composed Edge URLs bypass the adapter.

## Search findings and classification notes

- Repository search covered frontend modules, backend routes/services, Supabase functions and `_shared` code, migrations and consolidated schema, docs, scripts and GitHub workflows for `/functions/v1/`, `supabase.functions.invoke`, `fetch(`, `Deno.env.get`, service-role use, and named IoT/payment/Persona/notification call chains.
- There are numerous code-defined Edge calls beyond the table rows, including `send-approval-notification`, `send-payment-notification`, `send-outbound-email`, `send-push-notification`, `send-task-notification`, `send-booking-reminders`, and `booking-email-trigger`. Their source Edge functions and database triggers are retained pending endpoint-by-endpoint migration and live schedule verification.
- A frontend `supabase.functions.invoke()` scan found three previously uncovered production calls (`proxy-create-payment`, `send-email-notification`, `emergency-sos`) and one test-only call (`paystack-init`). The production calls now use the gateway set. `emergency-sos` remains Edge-backed via the known-function proxy and is deliberately not classified as authoritative; `paystack-init` remains an obsolete/test-only fixture to investigate.
- `backend/src/routes/functions.ts` now rejects names absent from both the authoritative backend set and the Edge Function catalog before attempting upstream proxying. Catalogued Edge functions may still be proxied; this is not a claim that they execute locally.
- The TTS browser requests were moved to the raw BackendBridge path, which preserves binary responses and avoids a browser-to-Edge URL. Cloud Run still proxies the current Edge TTS implementation, so the provider operation itself remains un-migrated.
- Supabase Auth, database access/RLS, Storage, REST, and documented native operations are intentionally retained.
